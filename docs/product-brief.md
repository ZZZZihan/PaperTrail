# 单篇论文证据问答：产品说明草稿

版本：v0.1 · 2026-09-05 · AI 整理，真实阅读经历与人工证据待补充。
关联任务：[COL-10](https://linear.app/colife/issue/COL-10)。

## 用户与情境

第一位用户是本人，阅读方向为 LLM / Agent 论文。后续同学试用作为独立反馈来源。
2026-09-05 用户补充：“到时候找几篇 Agent 相关的吧。”因此选文和具体阅读案例留待后续，尚无已选论文、真实卡点或用户效果反馈。

## 待验证的问题

已有假设：阅读论文时，寻找关键结论对应的原文、确认结论是否被证据支持，会耗费时间。
当前解决方式、最费时步骤、改善价值仍待一次真实阅读经历验证；上述假设不能记录为访谈结论。

## 首版用户故事与范围

作为正在阅读论文的研究生，我希望上传一篇可提取正文的 PDF 并提问，得到带原文片段和 PDF 页码的回答，能够直接回到原文核对关键结论。

- 输入：单篇可提取正文的 PDF、自然语言问题。
- 输出：答案、支持答案的原文片段、PDF 物理页码、明确的任务状态。
- 价值假设：减少查找和核对原文的往返操作；需通过真实案例验证。
- 证据不足时限定为“在当前已检索证据中未找到支持”。解析失败、超时与取消要有明确状态。
- 先完成固定解析、检索、生成与引用校验；受控 Agent、多篇比较、扫描件 OCR、复杂图表理解和多人部署留待对应阶段。

## 两题核对材料

| 材料 | 有依据的问题 | 证据不足的问题 |
| --- | --- | --- |
| 论文标题、来源、固定版本 | 待选文 | 待选文 |
| 具体问题 | 待补充 | 待补充 |
| 预期结论或不足原因 | 待原文核对 | 待界定资料和核查范围 |
| 原文片段与 PDF 物理页码 | 待核对 | 记录实际检查过的章节和范围 |
| 人工核对人、日期和结论 | 未核对 | 未核对 |

PDF 物理页码从 1 开始展示，不能直接套用论文印刷页码。AI 后续可以协助找候选证据，人工核对需要单独记录。

## 当前结论与下一步

暂沿用单篇证据问答方向，需求价值尚未验收。用户已要求开始开发，先做不依赖选文的运行与检查基础；该准备工作不代表 COL-10 或 P0 完成。
后续选 Agent 论文时补齐一次真实阅读经历及以上两题，再据此收敛正式问答规则。
