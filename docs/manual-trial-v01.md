# v0.1 本地人工试用与反馈

本清单约 25 分钟，由用户实际操作后填写。AI 开发诊断与下面的人工产品验收、学习验收分别记录；未填写的项目均为待核对。

## 启动与准备（3 分钟）

在仓库根目录运行 `make serve`，访问 <http://127.0.0.1:8000/>。首次依赖准备见 [本地开发](local-development.md)。原文件及历史保存在 `data/library/` 与 `data/postgres/`，保留两部分才能恢复完整资料。

模型配置位于 `.env.local`，参考 `.env.example`。须填写服务 base URL（按供应商 API 前缀填写，通常含 /v1；客户端会追加 /chat/completions）、模型名称、密钥、获准预算、币种及输入/输出每百万 token 单价。不要将密钥粘贴到反馈、截图或仓库。配置变更后重启服务。日常开发可使用 `make dev`，试用使用无自动重载的 `make serve`。

选用你自己的文本 PDF，或从 `data/diagnostics/sources/` 选择准备的公开论文。这三篇仅为 AI 准备的开发样例，不意味着你已经读过。

## 主流程（10 分钟）

1. 上传一篇 PDF，确认文件名、页数、处理状态。打开原 PDF 和提取文字，检查至少一页的内容与物理页码。
2. 提一个具体的中文研究问题，例如“ReAct 为什么把推理与行动交替进行？”等候完成，记录是否能理解处理状态。
3. 阅读回答中的每条关键事实。逐条展开原文引用，判断片段是否真的支持这条事实，尤其注意范围、条件、数字和限定词。
4. 点击一条不在首页的引用，确认 PDF 跳到标注物理页。对照原 PDF，留意提取文字可能出现的连字、表格错序和跨行断词。
5. 再问一个实验条件或局限的问题。确认历史保留第一题，并能在两条答案之间查看。问题是独立处理的，若用“它”“刚才那个方法”，建议补充明确对象。

## 证据不足与恢复（5 分钟）

1. 问一个论文当前材料无法支持的具体问题，例如对 ReAct 提问“每个 WebShop 任务的模型调用费用折合人民币多少钱？”检查是否限定在当前已检索证据范围，而非用商品价格或外部常识代替费用。
2. 选择开发集中一题不足问题，看系统是否清楚说明不能支持，以及你是否知道如何改问或查原文。
3. 如果遇到失败，检查原问题是否保存、是否有可操作说明，再决定主动重试。重试可能再次产生模型费用。
4. 若需要手动验证配置缺失：先安全备份 `.env.local`，暂时清空模型名称并重启，确认有明确提示且论文与历史仍可用，再恢复配置。超时/无效引用的可重复故障注入证据由开发记录提供，无需更换真实凭据制造故障。

## 刷新与重启（4 分钟）

1. 刷新网页，确认选中的论文、问题、回答、引用仍可查看。
2. 记录一题的问题 ID、回答或引用文本，Ctrl+C 停止服务，执行 `make db-stop`，再运行 `make serve`。
3. 再次打开同一篇论文，核对记录一致，点击引用继续查看。不要删除 `data/` 来重启。
4. 如果恰好处理中断，应显示中断而非永久加载；系统不会自动续调模型。

## 理解实现（3 分钟）

以下由你用自己的话回答，AI 不能替你填“已掌握”：

- 一个 PDF 怎样变成回答里可以点击的证据？页码从哪里来？
- 引用能打开，为什么还不等于它支持回答？
- 检索没有找到证据，为什么不能写“论文没有提到”？
- 模型超时后为什么保留失败记录、由你主动重试？
- 你想修改分块大小或检索数量时，应该查看哪些代码与诊断结果？

实现入口见 [规格与数据流](evidence-qa-v01.md)。

## 反馈模板

复制以下内容，每个问题单独填写；可附不含密钥的截图。

```text
日期 / 版本 SHA：
论文文件名 / SHA-256 / PDF 页数：
问题 ID（或提问时间）：
我输入的问题：
实际回答或错误：
我预期系统应该怎样表现：
引用片段 / PDF 物理页码：
原文是否支持这条事实：是 / 部分支持 / 不支持 / 不确定
不一致的条件、数字或遗漏：
页面是否能顺利找到引用与历史：
刷新 / 重启结果：
能否再次复现，具体步骤：
影响：无法继续 / 会误导判断 / 不便但可继续 / 建议
```

人工结论：产品效果 **待核对**；学习掌握 **待核对**。工程检查通过和 AI 诊断成绩均不能自动填写这两项。
