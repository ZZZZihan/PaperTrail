# v0.1 本地人工试用与反馈

本清单约 25 分钟，由用户实际操作后填写。v0.1 的工程实现与真实模型开发诊断已完成，当前准备用户试用。AI 开发诊断与下面的人工产品验收、学习验收分别记录；P0 真实阅读需求和人工样例、未填写的试用项目均为待核对。

## 启动与准备（3 分钟）

当前本机已配置真实模型 `gpt-5.6-sol`，可直接访问 <http://127.0.0.1:8000/>。若服务未启动，在仓库根目录运行 `make serve`；无需为了开始试用重复配置模型或重置预算。原文件及历史保存在 `data/library/` 与 `data/postgres/`，保留两部分才能恢复完整资料。

本轮使用已获准的现有中转额度，预算模式为 `provider_quota`，持久账本累计上限为 160 次模型调用，每题最多 3 次；已有开发诊断与后续人工提问共用本轮账本，160 不是当前剩余次数。所选模型费率未知，费用记录保留未知，不能套用 mini 或其他模型单价。若提示调用上限已到，先核对本轮用量与供应商额度；刷新、重启或换模型不会重置上限。

最终 v3 的核心代码为 `314d9f182f90cf6e77a32c18340172091b4ee62e`。真实开发集返回 10 个回答、5 个不足提示；独立 AI 核对为 9/10 可答题完整、1 题部分覆盖，5/5 不足提示恰当，17 处引用均通过存在与归属校验。逐题结果见 [诊断记录](../evals/development-v0.1/results-2026-09-05.json)，最新提交、`make check`、浏览器操作与重启证据见 [本轮验证记录](verification-col-18.md)。这些检查不代替本清单中的人工核对。

已知质量问题值得在试用中重点检查：`react-03` 的主模型与示例数正确，但正文遗漏了模型冻结与人工编排轨迹的实验条件；不足提示的下一步建议也较通用。请记录你自己的判断，不因 AI 已检查而跳过原文。

在其他机器首次启动时，先按 [本地开发](local-development.md) 安装依赖，在本地 `.env.local` 填写服务 base URL（按供应商 API 前缀填写，客户端追加 `/chat/completions`）、模型名称、密钥和服务支持的请求参数方案，并按实际授权选择以下一种预算模式：

| 模式 | 需要填写的预算配置 | 使用与记录规则 |
| --- | --- | --- |
| `priced` | `PAPERTRAIL_MODEL_BUDGET_MODE=priced`，获准的 `PAPERTRAIL_MODEL_BUDGET`、`PAPERTRAIL_MODEL_CURRENCY`，以及该模型真实的输入/输出每百万 token 单价 | 调用前预留金额，按已知用量与配置单价估算；估算不等于供应商账单，不能用其他模型价格代替 |
| `provider_quota` | `PAPERTRAIL_MODEL_BUDGET_MODE=provider_quota`，明确获准使用现有供应商额度，并填写该轮 `PAPERTRAIL_MODEL_MAX_CALLS`；币种须与同范围既有账本一致 | 不需要填写金额或单价，费用记为未知；持久统计当前账本范围的历史、失败和未完成调用，达到次数上限后停止 |

两种模式都保留 `PAPERTRAIL_MODEL_BUDGET_SCOPE` 对应的本轮账本，不通过改 scope 绕过已经消耗的额度。已有费用未知的配额调用时，不能切回金额模式把它们当作零。具体单价变量名与请求参数方案见 [本地开发](local-development.md)。不要将密钥粘贴到反馈、截图或仓库；配置变更后重启服务。日常开发可使用 `make dev`，试用使用无自动重载的 `make serve`。首次在其他机器安装与配置的时间另计，不包含在下面约 25 分钟的人工流程中。

选用你自己的文本 PDF，或从 `data/diagnostics/sources/` 选择准备的公开论文。这三篇仅为 AI 准备的开发样例，不意味着你已经读过。

## 主流程（10 分钟）

1. 上传一篇 PDF，确认文件名、页数、处理状态。打开原 PDF 和提取文字，检查至少一页的内容与物理页码。
2. 提一个具体的中文研究问题，例如“ReAct 将哪两种能力结合起来，它们如何配合？”等候完成，记录是否能理解处理状态。
3. 阅读回答中的每条关键事实。逐条展开原文引用，判断片段是否真的支持这条事实，尤其注意范围、条件、数字和限定词。
4. 点击一条不在首页的引用，确认 PDF 跳到标注物理页。对照原 PDF，留意提取文字可能出现的连字、表格错序和跨行断词。
5. 再问一个实验条件或局限的问题。确认历史保留第一题，并能在两条答案之间查看。问题是独立处理的，若用“它”“刚才那个方法”，建议补充明确对象。

## 证据不足与恢复（5 分钟）

1. 问一个论文当前材料无法支持的具体问题，例如对 ReAct 提问“每个 WebShop 任务的模型调用费用折合人民币多少钱？”检查是否限定在当前已检索证据范围，而非用商品价格或外部常识代替费用。
2. 选择开发集中一题不足问题，看系统是否清楚说明不能支持，以及你是否知道如何改问或查原文。
3. 如果遇到失败，检查原问题是否保存、是否有可操作说明，再决定主动重试。重试可能再次产生模型费用。
4. 若需要手动验证配置缺失：先安全备份 `.env.local`，暂时清空模型名称并重启，确认有明确提示且论文与历史仍可用，再恢复配置。超时/无效引用的可重复故障注入证据由开发记录提供，无需更换真实凭据制造故障。

## 刷新与重启（4 分钟）

当前预览由 Codex 开发会话保持运行。若你没有启动它的终端，可让 Codex 停止或重启当前预览；在任意其他终端按 Ctrl+C 无法停止这个已有服务。自己在终端运行 `make serve` 后，再使用该终端的 Ctrl+C 停止应用。

1. 刷新网页，确认选中的论文、问题、回答、引用仍可查看。
2. 记录一题的问题 ID、回答或引用文本，按上方说明停止应用，再执行 `make db-stop` 和 `make serve`。
3. 再次打开同一篇论文，核对记录一致，点击引用继续查看。不要删除 `data/` 来重启。
4. 如果恰好处理中断，应显示中断而非永久加载；系统不会自动续调模型。

## 理解实现（3 分钟）

以下由你用自己的话回答，AI 不能替你填“已掌握”：

- 一个 PDF 怎样变成回答里可以点击的证据？页码从哪里来？
- 引用能打开，为什么还不等于它支持回答？
- 检索没有找到证据，为什么不能写“论文没有提到”？
- 模型超时后为什么保留失败记录、由你主动重试？
- 你想修改分块大小或检索数量时，应该查看哪些代码与诊断结果？
