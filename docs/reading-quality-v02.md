## 用户行为与完成判据

1. 阅读简介时能理解研究问题、术语在本文的含义、方法输入/过程/输出、实验依据与必要条件、结论及范围。
   论文陈述、作者解释、教学示意和系统推断采用不同标签，后两类也不能添加无依据的论文事实。
   关键内容均能回到原文，成功结果持久保存。旧缓存不伪装成已通过新规则。
2. 提问后分别看到有依据的回答与要点覆盖情况；事实有据但条件或子问题遗漏时，显示部分回答与待核对项。
   通过支持检查的部分内容保留；无支持的断言只留在诊断追踪，不进入答案。
3. 当前引用原文存在、身份与归属校验保持；覆盖检查是 AI 判断，不等于人工评分。
   “当前已检索证据不足”不等于论文绝对没有答案，纠正有直接反证的前提可以是完整回答。
4. 页面、历史、刷新与必要重启保留新数据及旧论文/问答/账本。完成后给出试用入口、实际验证范围与未完成项。

## 固定问答流程

模型整理检索词和 1—12 个中性问题要点 → 既有 BM25 检索 → 模型按要点生成引用事实 →
程序引用检查 → 一次独立模型调用分别判断事实支持与要点覆盖。

要点整理只能看到用户问题，没有评测题号或预期答案。生成阶段必须把相关必要条件写在正文，
不能依赖引用里附带的细节。覆盖检查读取问题、要点、回答与本次检索上下文，
逐项核对，并可补充 0—8 个上下文显示的必要限定；事实支持仍只能依据该条事实所附原文。

`coverage` 是持久 JSON：`status = complete / partial / unanswered`、
`review_source = ai / not_checked`、`items`（要点、中性来源、是否覆盖、关联的已发布事实索引、诊断理由）。
支持不通过的事实被移除后，所有关联覆盖项不得继续记为覆盖，索引重算到实际发布事实。
缺失、重复、越界或非布尔判断导致检查失败，不能假定完整。

终态：`answered`（存在支持事实且全部已识别要点覆盖）、`partial_answer`（存在支持事实但有缺项）、
`insufficient_evidence`（本次没有可发布事实）、`failed`（配置、格式、校验或运行失败）。
旧任务的 coverage 为 null，界面明确旧回答尚未按新规则检查；不回填推测结果。

仍为固定最多 3 次模型调用、180 秒总期限，无自动重试。当前没有引入新检索模型、向量数据库或 Agent。
本次首先解决已找到条件但正文遗漏的问题；检索充分性由独立诊断评价，不能用短语命中代替。
