# 单篇论文证据问答 v0.1

日期：2026-09-05。关联 [COL-18](https://linear.app/colife/issue/COL-18)。这是本轮实现规格与开发验收规则，用户已授权直接实施。AI 准备的开发样例、AI 语义检查、用户产品效果验收、用户学习验收分别记录；COL-10—COL-14 的原有人工条件没有因此完成。

## 输入、输出与边界

沿用 [PDF 导入规则](pdf-import.md)，单用户在本机论文库选择一篇可提取文本的 PDF。每次提问只使用该论文，中文问题去除首尾空白后长 1—2000 字符。问题独立处理，不隐式把上一轮答案当作证据。原 PDF、逐页文本和已保存问答均可在刷新、应用及数据库重启后查看。

答案由若干关键事实组成，每条事实附一个或多个原文片段和 PDF 物理页码。物理页码等于数据库 page_index + 1，与印刷页码可能不同。点击引用跳转到当前论文对应页；片段来自保存的提取文字，图表、公式和文字顺序仍需对照原 PDF。

本轮不含扫描件 OCR、自动寻找/下载论文、多篇比较、Agent 循环、多用户及公网部署。下载公开论文只用于准备开发样例，不构成自动找论文产品能力。

## 可观察行为

| 场景 | 行为与下一步 |
| --- | --- |
| 正常提问 | 先持久保存问题并返回任务 ID，显示处理阶段；完成后保存答案、片段、页码和运行信息 |
| 当前已检索证据不足 | 明确显示“在当前已检索证据中未找到足够支持”，不据此断言整篇论文没有相关内容；可改问更具体的问题或查看原文 |
| 模型配置缺失 | 显示缺少本地模型配置和配置入口，不返回模拟答案；已保存论文与历史继续可用 |
| 模型超时、网络或服务失败 | 保存失败状态及安全的错误原因；保留原问题，用户可主动重试；无自动重试、无隐性重复收费 |
| 引用标识、归属或片段不合法 | 拒绝展示为有效回答，保存 invalid_citation；不把模型提供的页码直接信任为来源 |
| AI 判断引用不支持关键事实 | 不作为有依据的答案发布，显示证据不足/校验失败；与程序引用校验分别记录 |
| 刷新、离开论文 | 后端任务与前端页面生命周期分离；再次打开时从数据库读取状态和历史 |
| 应用在处理中停止 | 下次启动把未结束任务标记为 interrupted，告知调用可能发生且费用未知；不自动续调模型 |
| 重复提交 | 同一 request_id 返回同一任务，不重复调用；相同 request_id 搭配不同内容拒绝；主动重试使用新 ID |
| 已有任务进行中 | 本地版本每次只执行一个问答任务；明确提示等待，避免并发费用及状态混乱 |

## 固定数据流与设计

1. pypdf 逐页解析，PostgreSQL 保存 paper、pages，本地保存原件；保留 COL-16 原有数据。
2. 从当前论文页面生成有确定 ID 的片段；片段不跨页，记录原文范围、论文 SHA 和分块版本。已有论文可直接使用，无需重传。
3. 固定一次查询转换，把中文问题转为适合英文论文的检索词；在当前论文内按 BM25 排序，限制片段数及上下文总量。检索方案需在固定样例上与简单词法起点比较，记录召回差异后确定参数。
4. 固定一次结构化生成：模型只能根据提供的片段回答，逐条事实选择 chunk_id 和原文 quote，或者报告不足。论文文字是待分析数据，不能赋予权限；没有外部工具。
5. 程序检验 chunk_id 在本轮检索集合内、属于当前论文，quote 在对应片段内（只规范空白），页面从可信记录解析。每条事实必须有引用。
6. 独立的固定语义检查评判每条事实及引用是否支持，不做开放式补检索。AI 检查有误判可能；人工核对继续待定。
7. 保存任务终态、事实/引用快照和运行追踪。前端轮询任务，历史从 PostgreSQL 读取。

优先使用不新增向量数据库/嵌入模型的可解释起点：单篇论文规模小，页内 BM25 容易复现和核对；查询转换处理中文与英文词汇差异。限制是跨语义改写、表格和复杂跨段推理可能召回不足。若诊断发现系统性缺口，再依据实测调整；不得用预期答案或题目 ID 作为产品检索规则。

数据库只做增量建表：questions 外键连接 papers，保存 question、状态、阶段、结果 JSON、trace 和时间戳。启动恢复只适用于单进程本地服务；多实例任务调度不在本轮范围。应用异常不删除论文、页面或历史。启动先取得 session 独占锁；原连接丢失时拒绝新问答及后续模型调用，要求重启应用。读取历史、读取单题与新建问题时还会将超过 5 分钟的悬挂任务恢复为中断终态。

模型接口采用可配置的 OpenAI 兼容 Chat Completions，凭据只在忽略的本地配置中。按调用记录实际模型 ID、提示版本/哈希、参数、耗时、返回用量、可得费用；未知费用明确为未知。调用前必须具备用户允许的服务和预算。模型失败不输出凭据或原始上游错误正文。

## API 契约

- GET /api/config：原上传上限加 model 配置状态，永不返回密钥。
- POST /api/papers/{id}/questions：{question, request_id}，接受后 202 返回 Question。
- GET /api/papers/{id}/questions：按时间倒序的历史列表。
- GET /api/papers/{id}/questions/{qid}：当前论文下的单个任务。
- Question：id、paper_id、question、status、stage、claims、message、error_code、created_at、completed_at、trace。
- claims：[{text, citations:[{chunk_id,paper_id,page_index,quote}]}]。
- status：pending / running / answered / insufficient_evidence / failed。HTTP 层参数/不存在错误沿用 {error:{code,message}}。

## 开发诊断与评分

3 篇论文、15 题，其中 10 道有证据、5 道不足；固定版本、原文件 SHA、解析器版本及题集 SHA。全部标记 AI 准备、待人工核对。它们是开发集，不能声称通用准确率，也不能代替 P0 人工样例。

每题记录：输入、来源、预期要点/不足原因、参考片段/页码、实际回答、检索结果、引用程序检查、AI 语义支持检查、人工核对（初始 pending）、模型/提示配置、调用次数、耗时、token 用量和费用来源/未知原因。

开发目标：15/15 有定义终态；10 道可回答至少 8 道关键要点有支持；5 道不足均不编造答案；返回引用 100% 通过程序归属与存在检查。AI 检查成绩单独报告，不能填写成人工认可。未达目标时修复阻断主流程的问题并保留失败及重跑结果；如仍有质量缺口明确列出，不覆盖失败记录。
