## 1. 项目身份与目标

| 项目 | 用途 |
| --- | --- |
| PaperTrail | 论文研读 Agent 产品、Agent 全栈开发学习与求职作品 |
| mypaper | 独立的学术论文选题、开题与发表研究 |
| RepoPilot | 另一个独立的工程项目 |

PaperTrail 的目标是解决本人阅读 LLM / Agent 论文时理解和核对证据的实际问题，再邀请少量同学试用。首版聚焦单篇 PDF 的证据问答，逐步完成受控 Agent、多篇比较与恢复、部署试用。

能力参照沿用此前选定的 [天津小橙集团 AI Agent 开发工程师岗位](https://career.nankai.edu.cn/correcruit/content/id/116181.html)。项目应留下真实产品效果及开发者能解释、修改和验证实现的证据；这里的验收阈值是项目自己的学习与工程目标。

## 3. 已确定、建议与待补充

**已有基线：**

- 第一版输入为一篇可提取正文的 PDF 和自然语言问题；输出为答案、原文片段、PDF 页码和任务状态。
- 先固定解析、检索、生成与引用校验，再评估受控 Agent 补检索的收益；2—5 篇比较属于后续。
- 不足结论限定为“在当前已检索证据中未找到支持”；引用存在与引用真正支持答案分别检查。
- Linear 管任务、依赖和验收证据；GitHub 管规格、设计、代码与 PR。
- 采用需求→验收与样例→设计→任务→实现与验证→审查→发布→反馈的流程，按成果验收推进。
- 学习目标保留：Codex 可承担开发，用户需要理解、修改并验证核心实现。

**技术建议起点，尚未落地：**

Python / FastAPI、PostgreSQL、逐步加入 pgvector，前端 TypeScript / React；模块化单体，Docker Compose / CI。LangGraph、Langfuse 等按具体需要引入。没有既定依赖版本或已接入的付费模型。

## 5. Codex 接手操作顺序

1. 确认访问的是 PaperTrail 仓库和本文件列出的 Linear 项目；读取 AGENTS.md、项目基线、流程及最新任务。
2. 核对 Git 工作区改动、当前分支和最新提交，保留已有工作；核对最新任务状态，避免重复执行。
3. 简短汇报当前阶段、已验证成果、当前缺口和下一项动作，然后推进具备条件的工作。
4. 此次同步已核实仓库身份；后续可将仓库及交接链接补到 Linear 项目、历史流程文档及 COL-14 的相关记录中。不得因此将 COL-14 整体标为完成。
5. 按任务产出文档或实现；进入产品编码后，小步提交并关联 Linear issue，提供实际测试/评测证据。
6. 按真实验收结果更新任务；同时维护受影响的规格、决策与交接状态。

当前仓库没有应用依赖、启动方式、测试脚本或 CI 工作流。不要编造运行命令或测试结果；初始化应用时再写入可执行且验证过的说明。
