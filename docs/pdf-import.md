# PDF 导入与逐页核对

版本 v0.1，2026-09-05。关联 COL-16；用户已确认本轮范围。本文是实施规格，不代表人工验收完成。

## 用户流程和范围

上传一篇文本 PDF → 保存原件及逐页文字 → 列表重新打开 → 对照原 PDF 与同一物理页的文本。刷新、服务重启后仍可查看。网页支持桌面并排查看及窄屏切换。

每次上传一篇，单用户本地使用。文件初始上限 20 MiB、100 页；解析子进程时限 20 秒、同时最多 2 个。拒绝需要密码的 PDF。全文去除空白后没有可用文字时失败；个别空页保留位置。非空文字不等于排版或语义正确，复杂图表、公式、扫描件 OCR 留待后续。

## 数据与一致性

- PostgreSQL：论文 UUID、原始文件名、SHA-256（唯一）、字节数、页数、解析器版本、创建时间；页面主键为论文 UUID + 从 0 开始的物理页索引，保存提取文字。
- PDF 原件保存至配置的数据目录，以系统 UUID 命名；文件名仅用于展示。界面页码为索引加一，不用印刷页码替代。
- 上传先写临时文件，再由独立子进程解析；时限到达终止子进程。结果完整后，在数据库事务中按文件哈希加锁、再次去重、发布原件并保存全部页。
- 只有事务提交后才返回成功。普通异常回滚；提交结果不明时保留已发布原件，避免误删可能已提交的数据。进程被强杀可能留下未关联原件或 staging 文件，但不能产生半份成功的页记录；本轮不做自动清理或任务恢复。
- 重复上传返回已有论文；同名不同内容保存为不同论文。原件丢失时查看接口给出可理解的错误。

## API 与页面

- `POST /api/papers`：multipart 文件；成功 201，重复 200，返回论文信息与 duplicate。
- `GET /api/papers`：按创建时间倒序分页查询（每页 50）。
- `GET /api/papers/{id}`：论文详情与空白页索引。
- `GET /api/papers/{id}/pages/{page_index}`：读取单页文字，索引从 0 开始。
- `GET /api/papers/{id}/file`：只读取系统存储的原 PDF。
- `GET /api/config`：向网页公开文件大小、页数上限。

状态：网页本地显示上传/处理等待；请求结束显示成功、重复或错误。处理状态随请求存在，本轮无后台持久任务。无效文件/无文本/加密 422，超限 413，解析超时 408，并发繁忙/数据库不可用 503，存储故障 500。

## 验证

自动测试使用人工构造、明确标记的技术 PDF 和隔离 PostgreSQL，覆盖页码、空页、去重并发、同名不同文件、空正文、加密、损坏、上限、超时、事务失败与重开应用。另用公开 Agent 论文做解析核对和浏览器上传、翻页、刷新、重启演示；记录来源、哈希及检查范围，不当作 P0 人工问答标注。
