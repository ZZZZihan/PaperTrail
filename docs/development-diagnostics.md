## 复现与完整性核对

从仓库根目录执行：

```bash
uv sync --locked
uv run python scripts/fetch_diagnostic_papers.py
uv run python scripts/fetch_diagnostic_papers.py --verify-only
```

第一条脚本命令只下载缺失的三个固定版本，已有文件必须通过哈希校验，任何不匹配均停止，不覆盖文件。`--verify-only` 完全不访问网络；核对数据集文件、PDF 字节、页数、全部页的提取结果、首页版本标记，以及每个预期英文短片段的精确字符位置。均不导入应用论文库、不访问数据库、不调用模型。

当前解析器为锁文件环境中的 pypdf 6.17.0。逐页文本哈希按 `page.extract_text()` 的结果去除 NUL 后 UTF-8 编码计算；保留换行、空白和连字，不先做 Unicode 归一化。改变解析器或抽取规则可能改变文本哈希，即使 PDF 字节不变也要单独记录。页索引始终指从 0 开始的 PDF 物理页，界面页码为索引加 1；不依赖论文印刷页码。

源文件与题目集分别冻结：[checksums.sha256](../evals/development-v0.1/checksums.sha256) 锁定 `manifest.json` 与 [questions.json](../evals/development-v0.1/questions.json)。后续编辑题目必须形成新版本或明确更新冻结记录；每次模型运行保存其实际使用的这两份文件和校验和，不能覆盖旧运行。

## 数据格式与评分边界

`questions.json` 顶层包含 `schema_version`、`dataset_id`、来源标注、页索引约定、`expected_status_values` 和 `questions` 数组。每题字段如下：

| 字段 | 用途 |
| --- | --- |
| `id`、`paper_id`、`category`、`question` | 稳定题号、唯一允许论文、类别、实际中文输入 |
| `expected_status` | `answered` 或 `insufficient_evidence`；运行器可映射成应用状态，需记录映射 |
| `expected_answer_points` | AI 准备的中文关键结论，不是要求模型逐字复现的答案模板 |
| `expected_evidence` | 短原文定位片段，包含 `page_index`、`pdf_page_number`、`quote`、`char_start`、`char_end`、`section` |
| `allowed_source_scope`、`insufficient_reason` | 单篇来源边界；不足题为什么当前资料不支持 |
| `ai_review` | 样例准备的来源核对方法与注意点，不能当成生成答案已通过 |
| `human_review` | 全部 pending；保留用户核对人、时间、决定和备注字段 |

英文短片段有意用于定位，语义评分应打开同页对应章节读完整上下文；命中短片段本身不证明回答受到支持。运行时引用可选其他真正支持同一结论的当前论文片段，不要求机械命中同一短语。期望证据页可用于检索诊断，但最终正确性须检查系统真正返回的引用。

评分分三层保存，不互相代替：

1. **程序校验：** 引用标识存在、属于当前论文和本次已检索片段；页码、原文及引用选择合规。程序可以判定不合规引用失败，但不能声称已经证明语义支持。
2. **AI 诊断：** 对照关键结论与引用上下文，记录每题事实完整性、条件保留、是否越界、不足提示是否恰当。AI 检查生成结果的字段必须独立于本文件的样例准备检查。
3. **用户人工核对：** 实际打开原页，判断证据是否支持具体回答，并记录认可、不认可或待定。没有执行就保持 pending；独立记录产品效果与学习理解。

本轮开发目标为至少 8/10 可答题关键点完整且有依据、5/5 不足提示恰当、所有返回引用通过程序校验；最终独立 AI 诊断已达到该开发门槛。原 P0/P2 的人工认可仍需用户执行，不因 AI 达标而补写完成。模型超时、失败或配置缺失是工程状态，不能拿来计为不足题正确。

## 每次真实模型运行必须保存

每次创建新运行目录，至少保存源 PDF 和数据集哈希、代码 SHA 与是否存在未提交改动、应用版本、检索参数、分块版本、每题检索片段及分数、实际问题、结构化回答、原文引用、错误状态、模型服务与名称、提示版本及哈希、生成参数、开始时间和耗时、调用次数、token 用量、服务返回的费用或计价版本下的估算。不要保存密钥或 Authorization 头。

无法取得费用时保存 `null` 和原因，不写成 0；真实调用失败也要留存，是否已经计费不能凭客户端超时判断。模拟故障仅用于工程状态验证，并与真实模型问答结果明确区分。人工评分待定时如实记录，不以模型自动评分补写人工接受。
