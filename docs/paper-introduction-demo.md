# 论文简介 demo · COL-19

版本：2026-09-05。用户已授权实现并查看 demo；内容易懂程度与产品认可待用户试读。

关联 [COL-19](https://linear.app/colife/issue/COL-19)。本轮接在单篇证据问答工程基线之后；自动 Tag、分类和筛选是后续需求。

## 用户任务与内容

打开一篇论文，先理解关键术语，知道它试图解决什么问题，再理解作者提出的办法怎样运作。简介帮助用户决定继续读哪里，不能冒充完整论文或用户已经掌握。

内容采用一句话概括、研究问题、主要贡献、核心原理、结果与边界五项，以及 2—5 个关键术语解释。正文以约 300—500 中文字为写作目标，不作为机械字数截断；关键术语首次出现时顺带用通俗语言解释。方法机制说明关键过程、输入输出及与研究问题的关系，保留必要训练方式、冻结参数等条件。结果须同时保留论文的适用范围。综述、数据集、评测论文采用相应的组织思路或设计原理，不强行编造一种算法。

每一项内容和术语都绑定当前论文中的引用。术语解释限定于本篇论文的使用方式，不以模型常识补充无证据的定义。证据不足时说明当前所读文字的不足，不能把缺少支持写成原论文必然不存在某事。

## 交互与接口

- 阅读页默认显示“论文简介”，可切换“证据问答”；原 PDF 和逐页文字保留。
- 尚无简介时显示“生成论文简介”。点击后才调用模型；上传、进入页面、刷新和查看已有简介不调用模型。
- 生成过程显示状态；成功结果持久保存，失败可主动重试。网络中断保留提交标识，避免重复创建。
- 展开引用可读原文，点击可回到对应 PDF 物理页。明确区分 AI 生成、AI 支持检查与人工核对。
- `GET /api/papers/{paper_id}/introduction` 返回最近简介任务或 `null`。
- `POST /api/papers/{paper_id}/introduction` 输入 `request_id`，返回持久任务。已有成功或活跃简介复用；失败后允许使用新标识重试。
- 任务沿用 `pending / running / answered / insufficient_evidence / failed`。仅通过格式、引用及语义支持检查的内容写入可展示的 `introduction`。

成功内容结构为 `summary / problem / contribution / mechanism / evidence_and_limits`，各项为 `text + citations`；`terms` 每项为 `term + explanation + citations`。引用保存片段标识、论文标识、物理页索引和原文摘录。

## 固定生成流程与取舍

读取已保存的整篇文字 → 构造简介专用稳定页内片段 → 一次结构化生成并选择证据标识 → 程序从原文填入引用 → 引用存在/当前论文归属检查 → 一次独立 AI 支持检查 → 持久保存。

简介需要覆盖论文的整体思路，本 demo 先使用完整已提取文字，避免把局部问答检索结果当作全文概括。输入上限为原始文字 120,000 字符、证据片段 150,000 字符，超过时在模型调用前失败，不静默截断全文。完整文字仍不包含未正确提取的图片、公式或表格信息。

初版要求模型抄写引用，真实运行暴露了跨片段合并和符号改写。v3 改为每个 PDF 物理页按 1,000 字符无重叠分段，完整覆盖提取文字，标识绑定版本、论文、哈希、页和偏移。模型仅返回证据标识，引用正文由程序填入；模型自带引文或其他定位字段会被拒绝。普通问答的既有分块与校验不变。引用默认折叠，用户可展开看到支持段落。

最多两次模型调用，不自动重试，总处理期限 180 秒，沿用现有持久账本。首轮真实生成出现 45 秒单次超时后，简介专用单次窗口提高为至少 90 秒（仍受 180 秒总期限约束），普通问答配置不变。简介生成输出上限至少 5,000 tokens，以容纳结构和原文引用，实际请求参数进入账本。继续使用本机已获准的 `gpt-5.6-sol` 与原 scope，累计调用上限仍为 160；费率和实际费用未知。

简介复用现有任务与预算基础，数据库增量区分 `qa` 与 `introduction`，问答历史只显示问答。已有论文、问答和历史调用不删除或重记。活跃任务全局互斥及应用重启恢复约定继续适用。

## 开发样例与检查规则（真实运行前固定）

使用已有开发诊断集中的 Reflexion `2303.11366v4`、ReAct `2210.03629v3`、Toolformer `2302.04761v1`，沿用原 PDF 哈希与逐页文字。它们是 AI 开发样例，已经用于项目开发，不能称为未见测试集。

对每篇实际结果分别记录以下判据，使用完整/部分/不满足，不能只用应用状态代替：

1. 研究问题具体，能看出所处场景及已有做法的困难。
2. 贡献准确，清楚说明作者提出或发现了什么。
3. 原理讲清关键过程与作用关系，保留必要条件；特别核对 ReAct 的冻结模型及人工编写示例轨迹，Reflexion 的语言反馈与记忆使用，Toolformer 的工具调用样例筛选和微调。
4. 关键术语用常用词解释，没有用另一串未经解释的术语替代；在本篇论文中的用法有据。
5. 结果与范围相符，没有放大效果或编造局限。
6. 程序核对每处引用在原始页内片段中存在并属于当前论文；AI 另行核对语义支持和内容覆盖。用户理解程度另行待评。

确定性检查覆盖任务幂等/失败重试、问答隔离、非法/跨论文引用、支持检查失败、过长输入不调用模型与账本行为。执行 `make check`；真实浏览器查看简介、引用跳页和刷新，应用重启后核对持久结果。
