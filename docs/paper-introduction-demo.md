# 论文简介 demo · COL-19

版本：2026-09-05 · 研读卡 v1（生成流程 `paper-introduction-v6`）。用户已授权实现并查看 demo；内容易懂程度与产品认可待用户试读。

关联 [COL-19](https://linear.app/colife/issue/COL-19)。本轮接在单篇证据问答工程基线之后；自动 Tag、分类和筛选是后续需求。

## 用户任务与内容

打开一篇论文，先理解关键术语，知道它试图解决什么问题，再理解作者提出的办法怎样运作。简介帮助用户决定继续读哪里，不能冒充完整论文或用户已经掌握。

内容采用一句话概括、研究问题、主要贡献、核心原理、结果与边界五项，以及 2—5 个关键术语解释。正文以约 300—500 中文字为写作目标，不作为机械字数截断；关键术语首次出现时顺带用通俗语言解释。方法机制说明关键过程、输入输出及与研究问题的关系，保留必要训练方式、冻结参数等条件。结果须同时保留论文的适用范围。综述、数据集、评测论文采用相应的组织思路或设计原理，不强行编造一种算法。

每一项内容和术语都绑定当前论文中的 1—8 个原文片段引用；可选学习补充采用同一上限。普通问答每条事实仍最多 4 个引用。术语解释限定于本篇论文的使用方式，不以模型常识补充无证据的定义。证据不足时说明当前所读文字的不足，不能把缺少支持写成原论文必然不存在某事。

研读卡进一步区分四种内容来源；前五项正文与术语只能是前两类，不能用类比或推断替代论文主干。可按需要附加至多两项帮助理解的示意或推断，不要求每张卡强行凑齐四类。

| 来源类别 | 含义与支持规则 |
| --- | --- |
| `paper_statement` · 论文陈述 | 论文提出或报告的事实；所有细节必须受本项引用支持。 |
| `author_interpretation` · 作者解释 | 作者提出的解释、理由或假设；原文应支持这种归属，正文明确“作者认为/推测”，不能写成已证明的因果。 |
| `teaching_example` · 教学示意 | 根据所引机制构造的假设例子，明确标注“教学示意”，不能冒充论文中的实例、实验或测量结果；涉及的论文事实仍必须有据。 |
| `system_inference` · 系统推断 | 从所引证据做出的谨慎、带条件的推导，明确标注“系统推断”；不增加无据事实、因果确定性、普适效果或编造局限。 |

方法正文按输入、关键过程、输出的顺序解释，并写出影响理解的设置条件。例如冻结参数和人工编排轨迹不能只藏在引文里。实验部分将一个主要观察与其任务、比较对象和必要设置联系起来；不要求复述全部实验或精确分数。结论可用已经测试的范围限定，无原文依据时不强造一项“作者局限”。

## 交互与接口

- 阅读页默认显示“论文简介”，可切换“证据问答”；原 PDF 和逐页文字保留。
- 尚无简介时显示“生成论文简介”。点击后才调用模型；上传、进入页面、刷新和查看已有简介不调用模型。
- 生成过程显示状态；成功结果持久保存，失败可主动重试。网络中断保留提交标识，避免重复创建。
- 展开引用可读原文，点击可回到对应 PDF 物理页。正文与术语显示来源类别；展开“怎样区分论文结论与辅助解释”查看四类的含义。必要要点另显示 AI 覆盖检查，人工核对继续独立保留。
- `GET /api/papers/{paper_id}/introduction` 返回最近简介任务或 `null`。最新尝试尚未成功但存在旧成功结果时，附带 `previous_introduction` 及其任务标识；升级中或失败时继续展示旧卡并单独标明本次状态，重试创建新任务，不在旧成功和新失败之间空转。
- `POST /api/papers/{paper_id}/introduction` 输入 `request_id`，返回持久任务。已有当前版本成功或活跃简介复用；失败后允许使用新标识重试。旧版成功缓存继续展示，并明确尚未进行研读卡覆盖核对；用户主动“补全为研读卡”时发送 `refresh_if_outdated: true`，仅旧版缓存可新建，旧结果保留。查看、刷新或当前版本再次提交均不隐式重新生成。
- 任务沿用 `pending / running / answered / insufficient_evidence / failed`。仅通过格式、引用及语义支持检查的内容写入可展示的 `introduction`。

成功内容结构为 `summary / problem / contribution / mechanism / evidence_and_limits`，各项为 `text + basis + citations`；`terms` 每项为 `term + explanation + basis + citations`。可选 `learning_aids` 每项为 `text + basis + citations`，默认空列表。引用保存片段标识、论文标识、物理页索引和原文摘录。

程序在检查成功后写入 `schema_version: paper-reading-card-v1` 与 `coverage` 列表，每项含 `aspect`、布尔 `covered` 和中文诊断 `reason`。模型自称已检查或自填版本不能成为发布依据。历史内容缺少这些字段时不回填标签、成绩或新版本。

## 固定生成流程与取舍

读取已保存的整篇文字 → 构造简介专用稳定页内片段 → 结构化生成并选择证据标识 → 程序从原文填入引用 → 引用存在/当前论文归属检查 → 同一次独立 AI 调用分别检查逐项支持与必要要点覆盖 → 持久保存。如引用或语义未通过，允许根据明确核对意见修订一次，再完整检查；仍未通过则保留失败或不足状态。

简介需要覆盖论文的整体思路，本 demo 先使用完整已提取文字，避免把局部问答检索结果当作全文概括。输入上限为原始文字 120,000 字符、证据片段 150,000 字符，超过时在模型调用前失败，不静默截断全文。完整文字仍不包含未正确提取的图片、公式或表格信息。

初版要求模型抄写引用，真实运行暴露了跨片段合并和符号改写。v3 改为每个 PDF 物理页按 1,000 字符无重叠分段，完整覆盖提取文字，标识绑定版本、论文、哈希、页和偏移。模型仅返回证据标识，引用正文由程序填入；模型自带引文或其他定位字段会被拒绝。普通问答的既有分块与校验不变。引用默认折叠，用户可展开看到支持段落。

从 v5 起，独立检查返回两个相互独立的列表：

- `verdicts`：每条正文、术语和可选学习补充的支持与来源类别是否恰当。只允许使用该条自己所附引用，不能借完整论文中的未附证据补救一条缺少支持的说法。教学示意允许假设对象，但不豁免其中的论文事实；系统推断仍需所引证据支持。
- `coverage`：针对 `research_problem / terms_in_context / method_flow_and_setup / evidence_and_conditions / conclusion_and_scope` 五项，结合完整已提取正文核对简介主体是否漏掉必要要点。已找到、已引用但没有写在正文的条件依然算遗漏。学习补充不能替代主干内容；核对范围为简洁研读卡，不要求复制整篇论文。

任何一项缺失、重复、格式无效都不能以其他项通过推断为已完成。支持为真而覆盖为假时仍触发一次修订；修订后仍有遗漏则不发布研读卡，保留具体反馈和原稿。检查理由是 AI 诊断，不作为新的论文事实直接展示在简介正文。界面展示覆盖项与状态，用户可在原文中核对。

正常使用两次模型调用；发生一次内容修订时最多四次。修订输入包含原文、初稿与具体核对意见，要求删去无据断言或补齐对应依据，并保留核心原理的必要条件。两轮候选和检查结果均保留，不降低发布标准。网络、超时或 JSON 解析错误不自动重试。覆盖检查读取同一完整提取文字，因此其输入 token 数量高于只检查引文的旧版；调用数量和同一持久配额不变，v6 的时间窗口调整见下段。这是固定的一次修订，不是自主工具循环。

v6 的简介总期限为固定 300 秒，单次窗口至少 120 秒；各次调用共享同一个起始期限，遇到修订不重新计时，剩余时间不足时单次窗口会相应缩短。普通问答总期限仍为 180 秒、单次配置保持独立。简介输出上限仍至少 5,000 tokens，所有调用共用原持久账本，实际参数与期限进入追踪。继续使用本机已获准的模型与原 scope，累计调用上限仍为 160；费率和实际费用未知。

这项调整来自真实 v5 失败：运行 `20260905T084456.761581Z-8da9f20e4eab40319afc406d826c09cd` 四次调用分别为 30.620、33.837、26.780、88.679 秒，末次独立检查被 180 秒总期限剪断；该次结果是超时失败，末次质量判断未知。首轮的五项覆盖均被判通过，但原理段的跨页“按需”依据以及结果段的错误模式引用未配齐，触发唯一修订。修订结果段用满当时的 4 个引用，又加入冻结模型与人工分析限定，却没有同时附上这两个限定的原文。所有原稿和失败保留。

因此 v6 将简介每项来源空间扩至 8 个片段，并要求优先补上准确的相邻原文和必要设置依据：新增条件须同时在同一项补引用，不能借用其他字段的引用，也不能删除必要流程或条件求通过。引用原文、归属、逐条语义支持和五项覆盖标准不降低。时间窗口与引用容量的代码/离线边界验证不能证明新的真实请求必然成功；v6 真实验证及实际效果仍以 [本轮验证记录](verification-quality-v02.md) 为准。

简介复用现有任务与预算基础，数据库增量区分 `qa` 与 `introduction`，问答历史只显示问答。已有论文、问答和历史调用不删除或重记。活跃任务全局互斥及应用重启恢复约定继续适用。

## 开发样例与检查规则（真实运行前固定）

使用已有开发诊断集中的 Reflexion `2303.11366v4`、ReAct `2210.03629v3`、Toolformer `2302.04761v1`，沿用原 PDF 哈希与逐页文字。它们是 AI 开发样例，已经用于项目开发，不能称为未见测试集。

对每篇实际结果分别记录以下判据，使用完整/部分/不满足，不能只用应用状态代替：

1. 研究问题具体，能看出所处场景及已有做法的困难。
2. 贡献准确，清楚说明作者提出或发现了什么。
3. 原理讲清关键过程与作用关系，保留必要条件；特别核对 ReAct 的冻结模型及人工编写示例轨迹，Reflexion 的语言反馈与记忆使用，Toolformer 的工具调用样例筛选和微调。
4. 关键术语用常用词解释，没有用另一串未经解释的术语替代；在本篇论文中的用法有据。
5. 结果与范围相符，没有放大效果或编造局限。
6. 程序核对每处引用在原始页内片段中存在并属于当前论文；AI 另行核对语义支持、来源类别和正文内容覆盖。用户理解程度另行待评。
7. 方法正文明确输入、关键过程、输出；一个主要实验观察保留必要任务、比较和设置条件，引用里出现但正文漏写仍算遗漏。保持既有 ReAct 冻结模型与人工轨迹的严格要求。
8. 可选教学示意/系统推断不冒充论文实验或作者结论；相同原文引用校验与所有基础事实支持规则继续适用。

确定性检查覆盖任务幂等/失败重试、问答隔离、非法/跨论文引用、支持检查失败、过长输入不调用模型与账本行为。执行 `make check`；真实浏览器查看简介、引用跳页和刷新，应用重启后核对持久结果。
